## 结论摘要

批次 B：V2 Registry 已注册 `prepare_scene_packages` / `generate_scene_assets`；默认走进程内领域 Job + `M06ScenePackageOperationPort`。`video_agent_v2` 下脚本确认、模型确认、失败参考图重试提交 Supervisor Turn，不再直接 `startPrepareScenePackagesJob` / `startSceneAssetsJob`。`frontend_v2` 仍保留旧 Job 路径。Gateway 装配 `make_generate_scene_assets_runner` 才能真正生图。

## 核心逻辑

1. Tool → Operation Port → ProviderJobAdapter(Prepare/Generate domain service)
2. `generate_scene_assets` 标记 `confirmation_required=True`（计费闸门）；模型选择卡 / 确认卡可并存，后续可再收口到单一确认 API
3. Operation result 中的 http(s) URL 会去掉 query/fragment/userinfo 以满足安全合同；签名依赖仍应以 media-history 落库为准
4. FE V2 文案约定：`确认脚本并生成资产包` / `确认生图模型…开始生成参考图` / `继续生成失败的参考图`

## 注意事项

- 无 `scene_assets_runner` 时 Generate domain job 会立刻失败并提示「runner 未装配」
- 刷新/重启恢复依赖 Operation + Workspace，不依赖浏览器 pending Job（V2 路径）
- 不要在批次 B 删除 Gateway HTTP Job 端点；`frontend_v2` 仍依赖
