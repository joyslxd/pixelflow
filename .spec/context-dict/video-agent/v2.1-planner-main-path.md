## 结论摘要
V2.1 批次 A：`submit_turn` 主调 `VideoAgentPlanner.plan_turn()`（最多 3 个已注册 Tool 步骤）。Planner 缺失/超时/校验失败时只降级为单步 `inspect_video_workspace`，不再用 create/polish 确定性全表展开。`entry_path` 仍可写 workspace 诊断与成稿 episode 种子，但不决定步骤表。

## 核心逻辑
1. 组装 `VideoAgentPlanningContext`（workspace_digest + operation_summaries + blocking_confirmation）
2. `asyncio.wait_for(plan_turn, timeout≈45s)`
3. 失败 → `_inspect_fallback_plan`
4. 有 blocking confirmation 且本轮不像确认/取消 → 直接 inspect 冲突说明

## 注意事项
- 资产包 Tool 与 FE Job 旁路已在批次 B 收敛（见 `v2.1-batch-b-scene-package-tools.md`）；无 Planner 的单测会看到 inspect-only
- 旧「方案 1 entry_path LLM 展 steps」已废止；`entry-path-tier1-llm.md` 被本文取代

- 默认超时 45s（原 10s 易在结构化输出修复重试时误降级，见 `planner-timeout-inspect-fallback.md`）
- Planner 模型绑定优先 `json_schema`，并在 prompt 中附带 output_example / output_schema
