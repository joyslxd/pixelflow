# 视频分镜提示词去重与优先级压缩设计

## 背景

视频场景包当前同时保存结构化的 `storyline`、`shot_description`、
`narration`、`transition`，以及由这些字段预先拼接得到的 `prompt`。生成分镜视频前，
`_build_scene_video_prompt()` 又把 `prompt` 和上述结构化字段拼接一次，导致故事线、
镜头描述和旁白重复出现。

重复内容会显著放大最终提示词。Python 网关当前又在调用 content-app 前执行
`2500` 字符硬校验，因此较丰富的镜头描述会直接在 PixelFlow 内失败，既不会创建
content-app 任务，也不会产生对应消费记录。这个行为与“镜头信息完整优先”的创作目标
冲突。

## 目标

1. `_build_scene_video_prompt()` 成为分镜视频最终提示词的唯一权威组装入口。
2. 最终提示词固定包含且只包含一次：
   `视觉风格 + 故事线 + 镜头描述 + 旁白 + 转场`。
3. 保留镜头描述中的地点、主体、动作、景别、运镜、光影、声音和收束信息。
4. 采用确定性的字段级去重与优先级压缩，不增加额外 LLM 调用。
5. 删除 PixelFlow 的 `2500` 字符硬限制，不再粗暴截断最终提示词。
6. 兼容历史对话中已经保存的复合 `scene.prompt`，恢复旧任务时不再次重复拼接。

## 非目标

- 不修改 content-app 的请求 DTO 或供应商限制；content-app 的字符限制由用户在
  content-app 仓库单独调整。
- 不改变视频模型、画幅、清晰度、时长、参考图数量或生成端点选择逻辑。
- 不调整场景包确认、场景视频并行生成、失败重试、额度恢复和视频合并流程。
- 不引入新的配置项，也不增加每个分镜一次的 LLM 压缩调用。

## 方案选择

### 方案 A：结构化字段单一组装

场景包保存结构化内容，视频生成前由 `_build_scene_video_prompt()` 按固定顺序组装。
旧复合 `scene.prompt` 不再整体并入，只作为视觉风格的兼容来源。

优点：

- 数据来源和最终产物职责清晰。
- 去重结果稳定、可测试，不受 LLM 波动影响。
- 不增加调用耗时和费用。
- 镜头描述可以完整保留，不需要按字符数截断。

本次采用该方案。

### 方案 B：调用 LLM 二次压缩

在场景视频生成前让 LLM 重写最终提示词。该方案能做语义级压缩，但增加耗时、成本和
不确定性，还可能改写已经审核的 Plan 与场景包，因此不采用。

### 方案 C：给字段分配固定字符配额

按字段截断到固定长度。该方案实现简单，但可能切断时间轴、对白或关键动作，也无法保证
地点、主体、动作、景别、运镜、光影、声音、收束完整，因此不采用。

## 权威数据流

```text
最终确认的 plan.md
  -> 场景包生成
  -> 结构化字段
     - visual_style
     - storyline
     - shot_description
     - narration
     - transition
  -> _build_scene_video_prompt()
  -> 规范化与去重
  -> 风格 + 故事线 + 镜头描述 + 旁白 + 转场
  -> 场景视频能力校验
  -> content-app 视频生成接口
```

`scene.prompt` 不再承担“完整视频提示词快照”的职责。新生成场景包中，它只保留视觉
风格兼容值；结构化字段才是故事线、镜头描述、旁白和转场的权威来源。

## 最终提示词组装

### 字段来源优先级

1. **视觉风格**：优先使用当前 `VideoCreationContract.visual_style`。
2. **历史视觉风格兼容**：创作合同缺少视觉风格时，从旧 `scene.prompt` 的
   `视觉风格` 标签中提取；不能提取时才把仅包含风格的旧值作为兜底。
3. **故事线**：使用 `scene.storyline`。
4. **镜头描述**：使用 `scene.shot_description`，它是地点、主体、动作、景别、运镜、
   光影、声音和收束的权威载体。
5. **旁白**：使用 `scene.narration`。
6. **转场**：使用 `scene.transition`。

历史 `scene.prompt` 中已经拼接的故事线、镜头描述和旁白不得整体进入最终提示词。

### 输出顺序

非空字段按以下固定顺序输出：

```text
视觉风格：...
故事线：...
镜头描述：...
旁白：...
转场：...
```

标签只由组装器添加一次。字段值如果已经带有同名标签，先移除外层重复标签，再输出标准
标签。

## 优先级压缩规则

本设计中的“压缩”是确定性的去冗余，不是字符截断。

### 必须完整保留

`shot_description` 优先级最高，禁止按长度截断。其时间段、地点、主体、动作、景别、
运镜、光影、声音和收束信息必须原样保留，仅允许执行不改变语义的空白规范化和重复外层
标签清理。

### 可安全清理

对所有字段执行：

- 去除首尾空白。
- 把连续空格、空行和重复换行规范化。
- 去掉字段值外层已有的同名标签，避免 `故事线：故事线：...`。
- 去掉完全相同且连续出现的句段。

对视觉风格、故事线、旁白和转场执行跨字段精确去重时，只删除完全相同的完整句段，不做
模糊相似度判断，不改写句子。镜头描述中的内容不因其他字段出现相似信息而删除。

### 不允许的处理

- 不使用 `prompt[:2500]` 或任何固定长度切片。
- 不按字符配额删除镜头描述。
- 不通过关键词猜测后移除语义相近但不完全相同的句子。
- 不把完整旧 `scene.prompt` 作为第六个字段拼接。

## 历史场景包兼容

历史对话恢复时，`scene.prompt` 可能是以下复合内容：

```text
故事线：...
镜头描述：...
视觉风格：...
旁白：...
```

兼容规则：

1. 当前创作合同存在 `visual_style` 时直接使用合同值，忽略旧复合 `prompt`。
2. 合同缺失视觉风格时，只从旧 `prompt` 中提取 `视觉风格` 段。
3. 旧 `prompt` 无标准标签但明显只是单段视觉风格时，可以作为视觉风格兜底。
4. 无法安全判断的复合文本不整体拼接，避免重新制造重复内容。

这套兼容只影响最终提示词构建，不改写历史对话和已持久化场景包。

## 校验与错误处理

删除 `_validate_scene_video_request()` 中 `len(prompt) > 2500` 的失败分支，保留以下
现有能力校验：

- Seedance 单分镜时长范围。
- 模型支持的时长、画幅和清晰度。
- 参考图片、视频和音频数量。
- 各视频端点必需的首帧、尾帧或参考视频。

最终提示词长度由 content-app 当前合同和下游供应商负责。如果 content-app 返回真实
业务错误，继续沿用现有错误透传、三次异常重试、失败分镜展示和局部重生逻辑。

## 文档同步

`CONTENT_APP_API_CALLS.md` 中 `/api/video/reference-mode-video` 的说明需要删除
“PixelFlow 校验 2500 字提示词”，改为：

- PixelFlow 校验参考素材数量和实时模型参数。
- PixelFlow 不设置本地提示词字符硬上限。
- content-app 或供应商返回的提示词限制按真实业务错误透传。

若最新设计文档存在同类 `2500` 描述，也应同步修正。

## 测试设计

### 单元测试

1. **固定顺序**：输入五个字段，输出顺序必须为风格、故事线、镜头描述、旁白、转场。
2. **不重复拼接**：旧 `scene.prompt` 已包含故事线、镜头描述和旁白时，每个结构化内容
   在最终提示词中只出现一次。
3. **标签去重**：字段自带标签时，最终不出现重复标签。
4. **镜头完整度**：包含地点、主体、动作、景别、运镜、光影、声音和收束的镜头描述在
   组装后八项内容全部保留。
5. **超长提示词放行**：构造超过 `2500` 字符且其他参数合法的请求，Python 校验不得
   抛出字符上限错误，并应进入 Skill 调用。
6. **历史兼容**：无创作合同视觉风格时，从旧复合 `scene.prompt` 只提取视觉风格，
   不重复故事线、镜头描述和旁白。
7. **空字段处理**：旁白或转场为空时不输出空标签，其他字段顺序不变。

### 回归测试

- 场景视频端点选择保持不变。
- Seedance 时长、画幅、清晰度和参考素材数量校验保持不变。
- 部分分镜失败、重试、额度不足恢复和全部成功后合并行为保持不变。
- 前端失败原因仍展示 content-app 返回的真实错误。

## 验收标准

1. 之前因重复拼接达到 `3089` 字符的分镜不再被 PixelFlow 的 `2500` 校验拦截。
2. 最终提示词中故事线、镜头描述和旁白各出现一次。
3. 最终提示词包含风格、故事线、镜头描述、旁白和转场五类非空内容。
4. 镜头描述中的地点、主体、动作、景别、运镜、光影、声音和收束均未被截断。
5. 历史对话恢复后重新生成分镜视频时不出现重复提示词。
6. 现有模型能力、参考素材、并发、重试、额度和合并流程测试全部通过。
