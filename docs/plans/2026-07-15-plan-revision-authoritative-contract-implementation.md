# Plan 修订与权威执行合同实施计划

> 按 TDD 顺序执行：先让测试准确失败，再实现最小修复，最后扩展真实流程验证。

## 1. Plan 修订合同测试

- 在 `backend/tests/test_creative_plan_markdown.py` 增加视频 30 秒改 180 秒测试。
- 断言新版合同为 180 秒、每镜 4-15 秒、蓝图总和为 180 秒、Markdown 合同显示 180 秒。
- 增加图片尺寸和数量修订测试，断言新版图片合同同步更新。
- 增加 LLM 返回非法调度后的修正/兜底测试。

## 2. 修订上下文路由测试

- 在 `backend/tests/test_pixelflow_planning_router.py` 验证 `intake_context`、行业补充、附件和 PowerMem 上下文进入修订服务。
- 验证修订响应的合同和蓝图完整进入历史版本快照。

## 3. 实现结构化合同补丁

- 新增纯逻辑修订解析模块，负责白名单字段、显式数字/比例提取和合同合并。
- 扩展 Plan 修订 LLM JSON 合同，支持 `creation_contract_patch`。
- 修订函数使用新版合同调用 LLM、校验蓝图，并在必要时执行一次 LLM 修正和规则兜底。
- 图片和视频共用合同补丁入口，各自使用独立字段白名单。

## 4. 场景包最终蓝图继承测试

- 在 `backend/tests/test_video_scene_packages.py` 增加最终蓝图资产需求补齐测试。
- 验证故事线、旁白、镜头描述、转场不被场景包 LLM 改写。
- 验证角色、场景、道具逐项来自 `asset_requirements`，并映射为 `@asset_id` 和 mentions。
- 验证场景 prompt 由最终蓝图内容组装。

## 5. 实现场景资产对齐

- 汇总并规范化蓝图资产需求。
- 对 LLM 全局资产输出做名称匹配、漏项补齐和人物/道具分类校验。
- 按每个蓝图资产需求生成分镜引用，最多 9 张。
- 使用最终蓝图字段重建场景视频 prompt。

## 6. 图片最终合同测试与实现

- 在 `backend/tests/test_image_prepare.py` 增加最终 Plan 合同优先测试。
- 扩展图片 prepare DTO 和前端调用，传递 `creation_contract`。
- 在 prepare 入口合并最终合同，保证目标、风格、尺寸和数量优先使用最终版本。

## 7. 前端版本链路验证

- 补充或调整前端测试，验证最新 Plan 卡片携带完整合同和蓝图启动场景包/图片生成。
- 验证旧 Plan 卡片不可操作，恢复历史对话后最终版本仍可继续。

## 8. 自动化与真实验证

- 运行目标后端测试，再运行完整 PixelFlow 后端测试。
- 运行前端测试、类型检查和构建。
- 使用测试环境配置和用户提供的 Authorization，从采集开始跑图片、视频真实流程直到最终产物。
- 检查生成视频的总时长、场景包内容、资产和最终图片是否符合最终确认 Plan。

## 9. 合并与提交

- 提交前重新拉取远端分支。
- 如有冲突，按当前设计和最新远端逻辑智能合并。
- 重新运行关键验证。
- 使用中文提交信息提交代码和文档。
