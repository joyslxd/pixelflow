# Plan 修订与最终版本权威执行合同设计

## 背景

图片和视频 Plan 支持多版本修订、回退和最终确认。当前实现虽然保存了 `creation_contract` 和视频 `scene_blueprints`，但修订阶段仍把旧合同当成不可变输入，导致用户要求修改总时长、画幅、数量等执行参数时，新版 Plan 文本与结构化合同可能不一致。

视频场景包阶段虽然会沿用最终蓝图的故事线、镜头描述和旁白，但角色、场景、道具主要依赖场景包 LLM 的自由输出，未逐项校验最终蓝图中的 `asset_requirements`。图片生成准备阶段也仍可能优先读取最初表单，覆盖最终 Plan 合同。

## 目标

1. 当前激活 Plan 的 `creation_contract`、`scene_blueprints` 和版本号共同构成唯一权威执行合同。
2. 用户修改总时长后，每个视频分镜保持 4-15 秒整数，总和精确等于新版总时长。
3. 用户对风格、运镜、故事结构、模型、画幅、图片数量等提出修改时，LLM 必须结合当前 Plan、历史版本、采集上下文、行业补充、附件和用户意见生成新版本。
4. 视频场景包中的故事线、镜头描述、旁白和资产需求严格继承最终确认版本。
5. 图片生成参数优先消费最终 Plan 合同，不再被旧表单覆盖。

## 方案

采用“结构化合同补丁 + LLM 重写 + 强校验”的混合方案。

### 1. 修订合同解析

新增 Plan 修订合同解析能力：

- 从当前 `creation_contract` 复制出候选合同。
- 对用户明确提出的硬参数进行确定性提取，包括视频总时长、画幅、模型、清晰度，以及图片尺寸和数量。
- 允许 LLM 返回结构化 `creation_contract_patch`，用于补充风格、用途、故事表达等语义字段。
- 确定性提取到的用户明确值优先于 LLM 推断。
- 仅允许修改白名单字段，模型能力快照等未被用户明确要求修改的数据继续沿用当前合同。

### 2. Plan LLM 修订

修订 LLM 输入包含：

- 当前激活 Plan Markdown 和版本号；
- 当前结构化合同和分镜蓝图；
- 用户修改意见；
- 原始表单、选中创意、采集上下文、行业画像、附件摘要；
- PowerMem 检索结果，仅作为内部决策上下文；
- Seedance 分镜 Skill 规则。

视频修订输出包含完整 Plan、合同补丁、图片规格建议和完整 `scene_blueprints`。图片修订输出包含完整 Plan 和合同补丁。

### 3. 视频分镜校验与修复

- 先应用合同补丁并验证 `VideoCreationContract`。
- 使用新版 `video_duration_sec` 校验 LLM 蓝图。
- 每个分镜必须是 4-15 秒整数，时间线从 0 连续，总和精确等于新版总时长。
- 第一次校验失败时，把具体错误反馈给 LLM 修正一次。
- 再次失败时使用规则修复；若原分镜数量无法容纳新时长，则按新版合同生成符合总分总结构的兜底蓝图。
- 最终 Markdown 的制作执行合同和镜头列表由通过校验的结构化数据重新渲染。

### 4. 最终 Plan 到视频场景包

- 前端只允许最新可操作 Plan 卡片进入同意流程。
- 场景包 job 持久化最终 Plan 版本、Markdown、合同和蓝图快照。
- 故事线、旁白、转场和镜头描述直接来自最终蓝图。
- 镜头描述继续经过 Seedance Skill 的时间码和 `@asset_id` 规范化。
- 汇总全部蓝图的 `asset_requirements`，逐项生成角色、场景、道具；场景包 LLM 漏项时由后端补齐。
- 每个分镜的引用素材必须覆盖该蓝图声明的资产需求，最多 9 张，并生成对应 mentions。
- 分镜视频 prompt 由最终故事线、最终镜头描述、最终旁白和最终视觉风格组装，不再优先使用场景包 LLM 的自由 prompt。

### 5. 最终 Plan 到图片生成

- 图片 prepare 请求新增可选 `creation_contract`。
- 参数优先级固定为：最终 Plan 合同 > 用户确认表单 > 采集上下文 > 默认值。
- 图片目标、类型、用途、风格、比例和数量都从最终合同覆盖执行参数。
- prompt 仍包含最终 Plan Markdown，使语义内容与结构化参数保持一致。

### 6. 版本与恢复

- 每个 Plan 历史版本保存完整合同和蓝图快照。
- 回退后再次修订，从历史最大版本号继续递增。
- 场景包和图片生成只消费用户最终点击同意的 Plan 卡片快照。
- 会话恢复后继续展示并使用同一份最终快照。

## 错误与降级

- LLM 修订失败时不得伪装成成功修改硬参数；返回当前合同未能完成修订的明确错误。
- 结构化合同不合法时不生成下游产物。
- 视频蓝图可修复时保留 LLM 故事内容，仅调整调度；不可修复时才使用新版合同兜底生成。
- PowerMem 和行业补充失败继续 fail-open，但不影响当前 Plan 合同的一致性。

## 验证范围

1. 30 秒视频修改为 180 秒，合同、Markdown、蓝图总和均为 180 秒。
2. 连续生成 v2、v3 后同意 v3，场景包故事线、旁白、镜头描述和资产需求来自 v3。
3. 回退后再修改，版本号递增且执行回退后的新版本。
4. 图片 Plan 修改尺寸和数量后，prepare 使用新版合同。
5. LLM 返回错误总时长、漏资产或无效引用时，后端校验和补齐生效。
6. 真实图片和视频流程从采集开始执行到最终产物。
