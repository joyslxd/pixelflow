# PixelFlow 智能剪辑需求说明

> 状态：重设计评审稿，未开始实现。
>
> 更新日期：2026-09-14。
>
> 目标：用户提供素材与创作目标，Agent 自主选择合适的剪辑 Skill，结合素材证据调整结构、节奏和包装，形成可审阅、可修改的 Timeline，确认后渲染交付。

## 1. 需求依据与本次调整

本次参考[《BORG RISE 智能剪辑｜批量剪辑 PRD V1.7》](https://me72n0fj0n.feishu.cn/docx/KzL2dh5m2oUXi2xPvTXcwVqhnQg)，重点吸收第 2、4.2、8、9、10 章的模板结构、素材角色、评分证据、包装锚点及工程蒸馏规则。参考文档标注更新日期为 2026-09-14，性质为功能与交互评审稿，不能视为已上线能力。

该文档的主要交互是人工确认素材、选择固定模板，再按槽位匹配、配置包装和输出剪映草稿。PixelFlow 将其中可复用的剪辑方法沉淀为领域 Skill，由同一个通用 Agent 按需求和素材条件选择与适配。本文重设产品行为，不照搬原产品的四步页面、六文件夹或接口路径。

| 参考产品设计 | PixelFlow 需求决策 |
| --- | --- |
| 用户必须先选择模板，再填充固定槽位 | 默认由 Agent 推荐方法并形成方案；用户可指定偏好，但不必理解或手动选择 Skill |
| 整片与段落时长由模板固定、用户只读 | 原时长保留为参考配方；默认按用户目标和素材调整，用户明确锁定的约束必须遵守 |
| 内置模板、参考视频、我的模板 | 对应审核发布的方法库、参考风格分析、个人方案预设；不是三个强制页面步骤 |
| 逐素材分析、人工确认后入库 | 保留证据和确认机制；允许批量确认无冲突项，重点提示冲突和未知项 |
| 必需槽位缺素材则阻止匹配 | 保留缺口解释；Agent 可建议补素材、缩短时长或改方法，不能静默凑数 |
| 每种包装采用模板规则 | Skill 建议风格，事件绑定当前素材真实锚点，执行前由领域 Service 校验 |
| 不提供 MP4 或 Web 成片播放，仅剪映草稿 | 首期交付一份可播放、可下载的标准 MP4；剪映草稿是后续可选交付 |
| 批量组织多个剪映草稿 | 先做单方案闭环，后续支持显式指定数量的多方案/多成片，不自动批量渲染 |
| 工程蒸馏得到 TemplateSkill | 拆为方法 Skill、结构约束、资源依赖和来源审核信息；不能把整个执行合同塞进提示词 |

架构与部署沿用[智能剪辑技术方案](INTELLIGENT_VIDEO_EDITING_TECHNICAL_DESIGN.md)。本需求进一步定义 Skill 选择、适配和用户交互，后续实现前应将其补入技术合同；本次不新增运行代码、实际 Skill 文件或部署服务。

## 2. 产品定位与成功标准

产品面向电商商家、品牌运营、内容创作者和非专业剪辑人员。首期以电商剪辑方法验证完整闭环，通用素材分析和 Timeline 能力可继续服务品牌故事、记录片段等场景。

用户表达“把这些素材剪成一条突出使用体验的竖屏短片”，系统应能判断素材是否有口播、演示、痛点或行动引导，选择有依据的方法，并解释为什么这样剪。用户不需要先把素材放入五种角色文件夹，也不需要知道后台使用哪些 Tool。

成功标准：

- 用户不选模板，也能获得与目标、素材相匹配的可编辑方案。
- 同一剪辑方法面对不同素材，能产生不同选镜、时长和包装安排；不会机械填槽。
- 素材不足或方法不适用时，能指出缺口并提出实际可行的调整，不能编造内容。
- 用户可以锁定素材和结构、修正事实、替换镜头，并保留自己的修改。
- 每个成片可追溯到素材、方法版本、Timeline、资源和确认记录。

方法适用性和角色评分不代表销量、转化率或投放效果保证。

## 3. 输入、事实与素材复用

### 3.1 可用输入

- 用户上传并具有适用使用权的视频、图片、音频、Logo 和字幕。
- 当前用户有权使用的 PixelFlow 已生成素材及已登记素材库条目。
- 用户给定的用途、主题、平台、受众、时长、画幅、节奏、原声策略与必须保留内容。
- 已确认的品牌、产品、规格、价格、功能说明和行动指引。
- 授权清晰的音乐、音效、字体、贴纸与可用包装资源。
- 后续可选：合法提供的参考成片、个人方法预设及运营审核发布的工程蒸馏结果。

参考视频仅提供结构和风格证据，不自动成为成片素材，也不提供可继承的品牌、价格、人物、声音或产品效果声明。

### 3.2 素材理解与结构选择分离

素材先形成可复用的基础事实，再结合当前方案判断适配度。换一种剪辑方法不能要求整库重新分析；源素材、有效区间或相关分析版本变化时，才重算受影响结果。

分析包括媒体探测、独立音频分析、镜头与语义分析、技术质量检测。媒体探测读取时长、分辨率、帧率、音视频流、旋转和色彩；响度、语音区间和节拍属于音频分析，不是 FFprobe 元数据。内容理解提供主体、动作、对白、信息点、情绪和叙事用途；技术检测提供黑帧、冻结、模糊、异常曝光和截断区间。

结果必须带源素材、源区间、关键帧或转写引用、置信度，以及模型、字典和分析版本。质量、角色适配度、识别置信度分别展示。暗场、空镜或静止镜头不能只因分数低就被删除；存在创作意图的情况允许审阅和保留，解码损坏等硬错误仍需修复。音频不能当作画面槽位候选。

### 3.3 标签与人工确认

首期电商方法使用 `HOOK`（钩子）、`RECOMMEND`（种草）、`PAIN`（痛点）、`SELLING`（卖点）、`CTA`（行动引导）和 `UNKNOWN`。这是一组领域标签，不是所有视频必须具备的五个阶段。

- 标签字典由产品/运营版本化维护，模型从合法枚举中选择并附证据；未知保持未知，分析失败单独记为失败。
- 同一片段可具备多种角色，保留独立分值；角色分不要求加总为 100。
- 分析成功先进入待确认。无冲突项支持批量确认；低置信度、主体冲突、用途冲突和关键声明需逐项确认。
- 用户改用途时保存人工选择和原因，不篡改模型原分、置信度或证据。
- 只有本次任务引用、确认可用且满足执行约束的素材进入正式选镜候选；失败或未确认素材不阻塞其他可用素材的独立分析。用户可以明确暂不使用问题素材后继续。
- 从当前任务移出素材不删除源资产或其他任务的引用；引用失效或授权撤回时重新检查受影响方案。

原文阈值与评分权重可作为电商评测起点，不能直接当作全场景硬标准或已验证准确率。例如原文以质量 60、置信度 0.8、角色分 70 区分批量确认与逐项确认，PixelFlow 上线前需要人工标注集校准并版本化。可计算分值由 Service 统一计算，不接受模型无证据地产生总分；评分计算过程应可复现。

## 4. 从固定模板到剪辑 Skill

### 4.1 四种已有结构的转化

下表的原始结构和时长来自参考文档第 4.2 节；“适用证据”和“适配方式”为本次 PixelFlow 新设计。原始秒数是回归案例和起始配方，不是默认锁死的产品限制。

| 方法 | 原始模板配方 | 适用证据 | Agent 的适配方式与不适用处理 |
| --- | --- | --- | --- |
| 强节奏带货 | 钩子→卖点→痛点→CTA；30 秒，3/10/8/9 秒 | 有可理解开场、可信演示、实际问题与行动信息，用户追求直接表达 | 调整信息密度与段落长度；缺痛点证据时建议其他方法，不能编造痛点 |
| 口播种草 | 钩子→种草→卖点→CTA；30 秒，3/9/12/6 秒 | 口播可听清、有使用体验与产品依据 | 优先保留完整句子，用演示画面支持表达；没有口播或体验证据时不伪造用户评价 |
| 产品测评 | 钩子→痛点→卖点→CTA；30 秒，3/8/13/6 秒 | 有问题、测试/对比过程与可核实结论 | 保留测试条件和结论上下文；只有漂亮特写时不能包装成真实测评 |
| 上新展示 | 钩子→种草→卖点→CTA；24 秒，3/6/9/6 秒 | 产品外观、使用场景或功能展示充分，目标是介绍新品 | 按真实可展示信息组织镜头；无推荐证据时可明确建议改为场景展示结构，记录改动而不重标原素材 |

方法按复用价值组织 Skill，不按每个秒数、商品类目或视觉皮肤生成独立 Skill。多个方法可以复用基础选镜、对白保护、字幕和声音处理指导，但每种已发布方法需要自己的适用条件和案例。

对非电商目标，不强制引入 CTA 或痛点。首期至少提供基础顺剪/信息展示方法，确保用户没有营销目标或四种方法均不适用时仍有可解释的选择；超出首期能力的叙事要求应明确说明。

### 4.2 Skill 与执行合同分开

| 内容 | 归属 | 产品要求 |
| --- | --- | --- |
| 何时适用、如何选镜、为什么这样排序、如何调整节奏 | 领域 `SKILL.md` | Agent 能按素材条件加载、理解并应用 |
| 方法身份、版本、参考结构、可变项、必需信息和资源依赖 | 版本化方法档案 | 可查询、审阅、验证和回放，与 Skill 版本关联 |
| 本次选了哪些片段、各段实际时长、字幕/音乐和包装事件 | 权威 Timeline 与方案版本 | 用户可修改，执行读取同一份已冻结方案 |
| 素材权限、合法时间范围、资源兼容、用户锁定项、确认与费用 | Gateway Tool Broker/Service | 由代码强制，不靠 Skill 文案约束 |
| FFmpeg、ASR、音乐、动态包装、剪映草稿协议 | Provider Adapter | Agent 通过稳定业务 Tool 使用能力，不直接操作 Provider |

加载 Skill 是获得方法指导，实际动作仍调用分析、Timeline 修改、校验和渲染 Tool。不得为每个模板新建一个专用 Agent、固定工作流或只换名字的渲染 Tool。

### 4.3 每种方法必须说明什么

发布的方法至少包括：

- 名称、版本、描述、来源、适用目标和不适用条件。
- 所需素材特征、必要证据、最低信息完整性和可选信息。
- 参考段落结构、推荐时长或范围，以及哪些结构可以调整。
- 选镜、句子/动作完整性、同源复用、主体一致性与连续性建议。
- 字幕、标题、音乐、音效和包装风格建议及其触发依据。
- 必需资源、可选资源、兼容的渲染能力和明确的替代方案。
- 素材不足、证据未知、资源缺失及目标不匹配时的处理办法。
- 正例、反例、预期方案差异和测试记录。

方法档案不保存某次用户素材、实际字幕正文、价格或品牌声明。自然语言 Skill 中的建议即使更严格，也不能独立改变服务端权限和执行规则。来源文档、素材字幕和参考视频均属于待分析内容，不得成为系统指令。

### 4.4 三种来源与发布边界

1. **内置方法库**：首期由运营/研发把四种结构及基础方法整理为审核过的 Skill 和档案，按版本发布给 Agent。
2. **参考视频分析**：后续从合法参考提取结构、节奏、镜头与包装规律，形成当前任务的候选方法说明。只能估计成片可观察内容，不能声称还原剪映专有效果参数；未经审核不得自动安装为全局 Skill。
3. **个人方法预设**：后续允许保存当前方法的结构偏好、节奏、声音和包装选择。普通“保存我的方案”不自动授予修改运行时 Skill 的权限；私有预设按用户/租户隔离，复用时重新绑定当前素材与事实。

运营工程蒸馏作为后续生产方法的入口：校验可读取工程与资源→解析精确时间线→对齐语义→移除项目专属事实→抽取结构与事件规则→审核→替换素材测试→发布不可变版本。普通用户首期不提供“任意工程上传即变 Skill”的入口，不要求训练或微调模型。

每种方法至少用三组不同素材验证，并包含不适用或缺素材案例。原工程效果好不能证明方法普遍有效。历史方案继续关联旧 Skill 和资源版本；版本不可用时明确提示，不能静默换版本重放。

## 5. Agent 自主决策要求

### 5.1 决策依据与加载时机

Agent 根据当前需求和素材摘要识别剪辑任务，先获得可用方法的简短目录，按需加载候选 Skill 正文。不能把所有方法全文塞入通用系统指令，也不能仅凭商品类目、文件夹名称或方法流行度选择。

选择需要同时考虑用户目标、素材证据和完整性、参考风格、时长/画幅、原声需求、已有锁定项，以及当前可用资源和渲染能力。领域 Skill 提供取舍建议，能力档案提供事实，后端过滤不可执行选项。

### 5.2 方案形成

默认提供一份推荐方案，确有不同取舍时可同时提供一份简短备选说明；不会因展示备选而创建第二次渲染。用户应看到：

- 采用什么剪辑思路、为什么适合这些素材。
- 段落目的、选用片段、源区间、实际时长和顺序。
- 对原方法做了哪些调整、保留了哪些用户锁定内容。
- 声音、字幕、配乐、包装和输出规格。
- 仍有哪些缺口、不确定事实或需要用户选择的问题。

解释只提供可核对的事实与取舍摘要，不显示模型隐藏推理、系统提示词或内部 Tool 参数。用户界面使用“剪辑思路”“节奏”“方案”等表达，不要求用户理解 Skill、Provider 或 DTO。

### 5.3 自适应与锁定规则

- **默认自适应**：根据完整对白、动作、信息量和用户目标调整参考时长及镜头数量。改变方法核心结构时，在方案中明确说明原因。
- **明确锁定**：用户指定严格沿用某结构、必须保留某镜头或固定时长时，保存为本次方案约束。无法满足就解释冲突，不以“智能优化”覆盖用户选择。
- **不盲目缩放**：15 秒方案不能简单把 30 秒的每个片段播放速度翻倍；应重新选择完整的信息单元。固定时长由输出 Profile 定义误差容限，原文的 0.5 秒不直接扩展为所有输出标准。
- **素材缺口**：说明缺少的内容、证据或可用时长，并建议补充、换方法、缩短或明确取消可选段落。不能用冻结帧、循环、重复镜头或无关角色暗中凑时长。
- **可选替代**：用已确认字幕卡表达 CTA、用合法图片展示产品等需要记录为明确方案动作，不能伪造原素材拥有的语音或角色证据。用户锁定原声或禁止新增包装时必须遵守。
- **方法组合**：首期优先一个主结构，加兼容的字幕、声音和包装指导；组合前检查冲突，不把多个完整营销结构简单串接成超长成片。

Agent 可以自主选择方法、形成草案及修改可逆方案；付费分析、外部生成、正式渲染与导出仍遵守现有确认合同。已有有效确认按其范围复用，不重复打断用户；输入或费用范围变化时重新确认。

## 6. 用户旅程与界面要求

### 6.1 默认旅程

```text
用户提供素材与自然语言目标
  → 系统分析素材并展示证据，用户确认可用项与必要事实
  → Agent 选择适用方法，提出素材适配后的方案
  → 用户预览、修正、锁定或提出自然语言修改
  → 确认最终方案、输出范围与成本
  → 后台渲染、质量检查、上传和交付
  → 继续修改同一任务，或按需创建派生版本
```

这是用户可理解的旅程，不是强制每次重复的固定工作流。已确认素材可复用；一次局部修改无需重新走上传、分析和方法选择。失败或待确认状态要说明下一步，不通过页面前进按钮掩盖尚未完成的业务动作。

### 6.2 工作区展示

- **素材区**：原始素材、分析状态、角色建议、证据与确认状态；角色筛选不强制物理搬入文件夹。
- **方案区**：推荐思路、段落列表、缩略图、源区间、声音/包装说明及缺口提示。
- **修改入口**：自然语言修改、单镜替换、裁切、排序、字幕编辑、音量和原声选择、锁定/解锁、撤销和版本比较。
- **任务区**：排队、分析、待确认、渲染、质检、上传及终态；任务刷新、返回或关闭页面后继续存在。
- **交付区**：真实成片播放、下载、质量报告摘要及使用素材/授权信息；失败状态不能显示假下载入口。

首期方案预览包括源片段预览、时间线结构和文字/声音配置审阅，不承诺实时高保真复杂特效预览。若创建低清预览也需要异步渲染，须明确标记其规格、时间和适用费用，不能把它伪装成已完成的最终成片。

## 7. 选镜、包装和声音功能

### 7.1 选镜与连续性

先校验本任务引用、权限、确认、媒体通道、可用区间、必要证据、主体一致性及当前能力，再对合法候选综合比较角色、画质、动作/句子完整性、相邻连续性和包装空间。

缺少观测必须标未知，不能默认满分。方案适配分依赖当前结构与相邻镜头，不得在素材入库时宣称已算出对所有方案的适配度。确定性候选排序可辅助选择，但不替代 Agent 对主题和叙事的决策。

同一作品默认避免重复源区间；同源不同区间可在合法、必要且不重复信息的情况下使用。重复镜头作为回扣等明确创作手法时需在方案中可见，不用于隐蔽补时长。跨作品复用在多方案功能中展示复用程度，不承诺有限素材必然产生指定数量的高差异作品。

### 7.2 Timeline 修改

支持裁剪、排序、拼接、移出片段、静音、合法速度调整、画幅适配和基础转场。标题、字幕、图片、Logo、片尾署名及基础强调包装必须使用受控资源。

每次保存形成新 revision，撤销以恢复内容的新版本表达。Agent 修改必须保留已锁定内容；用户与 Agent 并发修改发生冲突时重新读取最新版本，不直接覆盖。

| 修改内容 | 应重算范围 | 必须保留 |
| --- | --- | --- |
| 换方法、改变总时长或结构 | 受影响选镜、时长和包装计划 | 原素材分析、人工事实确认、历史方案 |
| 替换或裁切一个镜头 | 本镜字幕/锚点、相邻转场及后续时间偏移 | 未受影响镜头、用户锁定项 |
| 改字幕文字或声音策略 | 对应字幕时间、混音与相关强调事件 | 未修改的选镜与结构 |
| 更换素材或撤销素材引用 | 依赖该素材的方案与可用性 | 其他源资产和其他任务 |
| 改输出画幅 | 裁切、安全区和兼容性 | 已确认叙事意图；必要变更明确展示 |

### 7.3 包装依据与时序

| 包装 | 应用依据 | 缺失或冲突时 |
| --- | --- | --- |
| 字幕 | 当前实际保留的语音或已确认配音、转写和词句时间 | 无语音不生成虚假对白；营销文案作为标题/文案卡单独标识 |
| 标题 | 当前作品主题和已确认事实 | 避免每镜重复弹出，不继承参考作品品牌和价格 |
| 花字/强调 | 当前关键词、产品演示或动作锚点 | 没有锚点就少用，不照抄参考片的绝对秒数 |
| 音效 | 动作、信息强调或镜头边界及授权资源 | 同锚点避免堆叠，人声优先；可选音效缺失时给出明确关闭方案 |
| 转场/画面效果 | 当前边界、节奏和可用能力 | 必需效果不支持则提示；可选效果用已同意的替代方案，不静默丢失 |
| BGM | 用户声音偏好、情绪、节奏和适用授权 | 没有合法可用素材时允许无配乐或请求补充，不任意下载 |

包装密度是上限，不是每隔几秒必须出现效果。优先保证字幕可读性、主体与事实展示，再考虑标题、强调和装饰。字幕安全区由输出 Profile 给出，不把复杂装饰当作智能程度的衡量标准。

所有事件绑定源锚点和目标时间线，裁切、变速、换镜后重新对齐；源锚点被裁掉就删除对应事件，不钳到片段边界制造假动作。方案预览、渲染与草稿导出共享一份事件计划，防止看到的方案与交付结果不同。

### 7.4 音乐、音效与混音

支持用户上传与已登记授权音频，后续扩展外部 Catalog 和可选音乐生成 Provider。记录来源、作者、许可证或授权声明、证据、署名及适用用途。能获取到文件不等于具有当前作品的使用权。

默认保留用户指定的原声；Agent 可推荐配乐，但必须显示声音方案。按需进行时长适配、淡入淡出、响度与峰值控制，在对白出现时压低背景音乐并保留必要环境声。上传完整配音时检查覆盖时长与内容一致性，缺失时不宣称已经完成配音。

Suno 仅是候选音乐生成接入，不作为首期依赖；官方接口、自动化方式和适用授权在实际接入前核实。剪映音乐资源同样经受控且允许的获取方式接入，不默认视为可下载的开源素材。

## 8. 输出、版本与长任务

首期支持 16:9 或 9:16 的单份标准 MP4，用户选择一种输出。默认不会同时生成母版、多画幅、无音乐版和字幕版；其他版本按需确认后创建。Web 播放与下载必须指向真实成功交付的 Artifact。

每个输出保存输入素材版本、使用方法及 Skill 版本、Timeline revision、包装事件、输出 Profile、质量报告和授权快照。模型建议过程可审计，已保存方案与冻结输入负责复现，不能只依赖重跑模型获得同一结果。

任务与执行分开：继续历史任务不新建创作任务，每次分析或渲染有独立可追溯执行身份。后台任务不因刷新、返回或关闭页面取消；取消要由用户显式请求并展示真实结果。仅重试失败项，保留已完成分析和已交付结果。

渲染期间允许用户继续编辑新版本，旧 Job 仍对应原冻结方案；旧结果不得覆盖新 Timeline。修改历史成片以新版本表达，不能伪装成原文件从未改变。页面状态来自 Gateway Snapshot/SSE，不以动画或前端内存模拟业务成功。

后续剪映草稿导出使用同一 Timeline 和事件合同，保留可编辑素材和资源映射；遇到不支持的效果明确处理。剪映工程是交付格式，不成为权威 Workspace。

## 9. 多方案与批量能力

从原文继承多次创作、跨任务素材复用和失败项重试需求，但不把批量渲染作为首期默认行为。

- P0：一份推荐方案，用户可以明确要求备选说明或修改版本，不自动生成多份成片。
- P1：用户指定方案数量、差异目标、素材复用策略、输出与预算，Agent 生成多份可比较的 Timeline，例如不同开场、叙事重点或包装密度。
- 批量计划记录各方案身份及差异，逐方案校验和确认；可一次确认明确列出的输出范围，但不能超出授权数量继续追加。
- 同一批内优先增加有意义的差异，显示同源复用及相似组合；素材不足以支持数量时说明可实现数量，不靠无意义排列凑数。
- 各输出独立 Job、独立结果；部分失败只重试失败项。方案分组属于业务视图，不恢复旧图片/视频 Batch、Child Operation 或 M06 生成编排。

## 10. 分期交付

| 阶段 | 必须交付 | 本阶段不承诺 |
| --- | --- | --- |
| P0：方法驱动的单片闭环 | 素材探测与候选镜头语义证据、确认/纠错、四种电商方法及基础方法、Agent 选择与适配、可编辑 Timeline、基础转场/字幕/静态包装、上传音频及已登记授权音频、基本混音与对白闪避、单份 MP4、质量检查、任务恢复 | 自动参考片解析、任意工程蒸馏、批量成片、复杂动态包装、剪映草稿导出 |
| P1：方法复用与多方案 | 参考结构/风格分析、个人预设、外部授权 Catalog、增强节拍/字幕、多方案与显式批量输出、经过验证的动态包装能力 | 未经审核自动发布 Skill、通用工程格式兼容 |
| P2：工程蒸馏与高级交付 | 运营剪映工程解析与审核发布、草稿导出、更多包装与 Provider、经需求确认的高级编辑能力 | 全量专业非线性剪辑软件能力 |

口播方法需要实际语音内容证据和时间对齐能力；P0 必须接入可用 ASR，或接受用户提供且经校验的转写/字幕。缺少二者时标记口播能力不可用，不用无内容证据的模板填充冒充智能剪辑。通用分析、主体一致性及方法适配是 P0 验收项，不再把核心语义理解全部推迟到 P1。

部署仍采用技术方案确定的单 Docker Worker、任务队列与 TOS。新增方法通常改 Skill 与方法档案，新增执行动作才扩 Tool；具体基础设施、租约和上传恢复不在本需求中重复设计。

## 11. 安全与明确非目标

- Gateway 是素材、Timeline、Job 和终态的权威写入方；所有修改验证用户、会话、revision、Run binding、Manifest、幂等及适用确认。
- Skill 不获得数据库、用户授权、Provider Secret、Shell 或宿主文件系统权限。FFmpeg 参数和包装代码由受控执行层生成。
- 方法版本和能力变化不能静默改变已确认方案；权限、资源授权及执行有效性在提交时仍需复查。
- 不自动删除原始素材，不采集或复刻未授权第三方作品，不继承参考片中的商品声明。
- 不让模型运行中自行安装、发布或修改官方 Skill，不从任意用户工程执行脚本。
- 不实现完整专业剪辑软件、任意插件、复杂三维合成或所有剪映效果兼容。
- 不把参考模板的每个 UI 控件、固定时长和 API 路径复制到 PixelFlow；Gateway 新接口继续以 `/agent` 开头。
- 日志、事件、仓库和测试夹具不保存用户正文、Secret 或 Provider 原始异常。用户可追溯方案存于有权限控制的业务存储。

## 12. 验收场景

以下使用授权或专门构造的非敏感测试素材。验收要验证实际方法选择、Tool 调用、Timeline 和输出，不仅断言提示词包含某句话。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 至少三段可用素材，用户只说目标、不选模板 | Agent 提出有素材证据的推荐方法和可修改 Timeline |
| A02 | 同一方法输入两组内容、时长不同的素材 | 选镜、段落时长或包装有所适配，不仅替换文件路径 |
| A03 | 有完整口播体验与演示，用户要求种草短片 | 优先考虑口播种草，保留句意，字幕对应真实声音 |
| A04 | 只有产品特写，用户要求测评 | 指出缺少测试证据，建议展示方法或补素材，不编造测评结论 |
| A05 | 素材缺 CTA，用户锁定原声和固定结构 | 提示缺口；不能自动新增虚假口播、跳段或用无关素材填充 |
| A06 | 用户把 30 秒参考配方改为 15 秒 | 重选完整信息单元，给出新方案；不能简单倍速全部片段 |
| A07 | 用户锁定镜头后要求换风格 | 保留锁定内容；不可兼容时明确说明冲突 |
| A08 | 模型角色与人工用途不同 | 保存两份来源，不伪造原分；仍验证权限、区间和主体一致性 |
| A09 | 暗场/静止镜头对叙事有用 | 可经审阅保留，不按质量分自动删除源素材 |
| A10 | 替换含对白的镜头 | 重算该镜字幕、事件及相关时间偏移，未修改部分保持不变 |
| A11 | 原动作锚点已被裁掉 | 对应强调事件消失或重新规划，不硬移到裁切边界 |
| A12 | 无合法 BGM 或必需包装资源不可用 | 明确缺口或经用户同意关闭可选项，不声称已使用不存在资源 |
| A13 | 未确认输入或过期确认直接调用渲染 | Service 拒绝执行，不产生未授权生成费用 |
| A14 | 队列重复、Worker 重启、页面关闭后继续任务 | 原任务恢复，成功结果保留，不重复发布或重复计费 |
| A15 | 渲染旧版本期间用户修改 Timeline | 旧结果关联旧版本，不覆盖最新编辑 |
| A16 | 成片发生解码错误、字幕越界或异常音轨 | 检查失败并给修复建议，不显示成功下载；美学疑点与硬错误分开 |
| A17 | 用户仅确认一个输出 | 只生成该规格 MP4，不默认输出多画幅和多个配乐版本 |
| A18 | 方法更新后回读历史方案 | 可查看原方法、Skill 和素材版本；不可用依赖明确提示 |
| A19（P1） | 同素材要求多份差异方案，部分输出失败 | 显示差异和复用程度，仅重试失败输出，不追加未确认数量 |
| A20（P1/P2） | 参考片或工程含其他品牌与专有效果 | 只提取有证据的方法，去除专属事实；不支持资源不假称还原成功 |

P0 发布门槛：四种方法与基础方法各完成至少三组素材的替换验证，并包含缺素材或不适用案例；完成一条“自然语言目标→分析确认→选择适配→修改→确认→真实 MP4 交付”的端到端旅程。记录方法选择合理性、用户修改量、无效参数率、失败恢复及端到端耗时，产品质量结论需人工审阅支持，不以单次成功样例代替评测。

## 13. 与研发技术设计的衔接

后续实施设计需要补齐以下合同，而不是直接把参考 PRD 的 `TemplateSkill` JSON 当作 Harness Skill 安装：

1. 方法档案与原生 Skill 的版本关联、可见范围和按需加载。
2. 素材基础分析、人工确认、候选适配和用户锁定项的领域合同。
3. 方法选择及适配结果如何写入权威 Timeline，哪些约束由 Service 强制执行。
4. 字幕、动作和包装事件的源时间与目标时间映射及局部重算。
5. 方法/资源快照、已确认方案与异步 Job 的绑定，用户 Turn 与各类恢复 Run 的一致性。
6. 个人预设和运营方法发布的隔离边界，以及后续多方案的独立输出身份。
