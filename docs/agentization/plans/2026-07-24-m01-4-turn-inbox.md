# M01.4 Turn Inbox 幂等与顺序领取实施计划

> **执行要求：** 使用 `superpowers:test-driven-development` 按任务顺序执行。步骤使用复选框跟踪；本计划只覆盖 M01.4，完成独立审核、一个中文提交和 push 后必须停止。

**目标：** 在 Memory/SQL `AgentRuntimeRepository` 中增加幂等 Turn 入队和按 conversation 串行领取能力，使网络重试复用同一 Turn，并阻止同一对话同时处理多个 Turn。

**架构：** 保留 M01.2 `create_turn()` 的“重复即冲突”底层语义，新增面向 Inbox 的 `enqueue_turn()` 和 `claim_next_turn()`。Memory 实现用同步内存状态转换保证单事件循环原子性；SQL 实现在同一事务中锁定目标对话的待处理/处理中 Turn，SQLite 使用 `BEGIN IMMEDIATE` 模拟行锁。

**技术栈：** Python 3.12、Pydantic v2、SQLAlchemy 2 async、SQLite/aiosqlite、pytest、ruff。

## 全局约束

- 不修改两个长期 feature 分支，不创建切片子分支或额外 worktree。
- 不新增表或 migration；M01.1 已提供 `inbox_sequence`、幂等唯一键和 owner queue 索引。
- 不修改冻结 `TurnRecord`/`TurnStatus` 线协议，不实现 M01.5 Event Outbox sequence/cursor/claim。
- `create_turn()` 继续用于严格插入和冲突检测；只有 `enqueue_turn()` 对同一 `conversation_id + client_input_id` 返回既有 Turn。
- 同一对话已有 `processing` Turn 时不得领取后续 Turn；领取只考虑 `accepted/queued`，成功后原子更新为 `processing`。
- 不调用真实图片、视频、PPT、剪映、LLM 或其他付费 API。
- 所有新增或修改的人工注释、计划、测试报告和 commit 使用中文主体语义。

- [x] **步骤 2：实现 Memory 幂等索引**

- [x] **步骤 3：实现 SQL 幂等入队**

### 任务三：实现按 conversation 原子领取

**文件：**

- 修改：`backend/pixelflow/agent_runtime/persistence/repositories.py`

**接口：**

```python
async def claim_next_turn(
    self,
    user_id: str,
    conversation_id: str,
) -> TurnRecord | None: ...
```

- [x] **步骤 1：实现 Memory 顺序状态转换**

按内部 `inbox_sequence` 读取 owner + conversation 下 `accepted/queued/processing` Turn；存在 `processing` 时返回 `None`，否则把最早 `accepted/queued` 深拷贝更新为 `processing`。

- [x] **步骤 2：实现 SQL 锁定领取事务**

非 SQLite 使用 `SELECT ... FOR UPDATE` 锁定 owner + conversation 的 `accepted/queued/processing` 行并按 `inbox_sequence` 排序；SQLite 在查询前执行 `BEGIN IMMEDIATE`。检测到 `processing` 返回 `None`，否则更新最早候选并在同一事务提交。
