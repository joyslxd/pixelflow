## 结构与边界结论

- `SummaryBuilder` 相当于应用 Service：首版只接受从 sequence 1 开始的连续消息；后续版只接受上一摘要覆盖终点之后的连续消息，并累计稳定 message ID、版本、前驱和覆盖终点。
- Engine 输入只包含上一版 `SummarySemanticSnapshot` 和尚未覆盖的 `SummarySourceMessage`；合同拒绝额外 `business_context`，也不接受 `WorkflowRecord` 或 `ContextEnvelope`。Plan、创作合同、资产清单、pending action 和 operation 不进入 Builder 输入。
- Engine 返回完整的新语义快照，因此可以正确移除已解决问题或替换旧决定；M04.5 `SummaryVerifier` 仍负责关键事实 100% 保留的最终 fail-closed 校验，本片没有提前实现该职责。
- `DeerFlowSummaryEngine` 不复制 token 估算、裁剪或模型调用逻辑；生产 factory 使用同一 DeerFlow model、token counter、trim 配置创建专用结构化 prompt 实例，原 middleware 和默认 prompt 不被修改。
- Builder 在 await 前冻结来源请求，并为 token 计量与异步摘要分别深拷贝；有副作用 Engine 不能污染后续调用或调用方消息/摘要对象。
- Builder 只返回可交给 M04.1 `StructuredSummaryRepository` 的 `ContextSummary`，不写库、不删除/改写原消息，不触发阈值、压缩锁、输入队列、事件或真实 LLM。
- 未修改冻结 DTO 字段、数据库表、migration、配置、长期 feature 分支、`status/BOARD.md` 或 content-app API 文档。
