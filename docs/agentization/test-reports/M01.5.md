## Event Outbox 合同结论

- `create_event()` 继续接收冻结 `AgentEvent`，但只允许 conversation 的下一连续 sequence；首个事件必须为 `1`，跳号、倒序、全局 event ID、conversation sequence/cursor 或跨 owner conversation 冲突均 fail-closed。
- `list_events_after_cursor()` 把 cursor 当作不透明锚点：`None` 从头读取，可见 cursor 返回其后事件，已到末尾返回空列表，未知或跨 owner cursor 返回 `None`，供上层映射为 404 风格；limit 限制为 `1..1000`。
- `claim_next_event()` 始终锁定 sequence 最小的未发布事件。有效租约阻止重复领取并阻止后续事件越序，过期租约允许其他 worker 接管且递增投递次数。
- `complete_event_delivery()` 只接受当前未过期租约；错误 worker、未领取或过期租约统一冲突，跨 owner 返回不存在。成功后标记 published，重复完成幂等返回原冻结事件。
- Memory 实现使用事件级异步锁并返回深拷贝；SQL 实现在单事务内查询和更新。SQLite 同 Engine 复用共享异步写锁、跨 Engine/进程使用 `BEGIN IMMEDIATE`，其他 SQL 方言使用 `SELECT ... FOR UPDATE`。
- M01.1 已预留全部 delivery/lease 字段，因此本切片没有修改数据库表、migration 或冻结 `AgentEvent` 线合同。
