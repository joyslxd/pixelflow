## 实现合同

- `WorkflowRegistry` 只按 `WorkflowKind` 解析唯一处理器；`FakeWorkflowRegistry` 缺失目标类型时 fail-closed，不隐式复用其他类型。
- 既有 Workflow 命令必须显式携带 `target_workflow_id`，只从 Supervisor 投影 Map 定位该目标；不使用 active 或最近任务兜底。
- `start_workflow` 必须携带预分配目标 ID，目标尚未存在，并从非 `general` intent 解析业务类型；不得覆盖已有 Workflow。
- 当前六类既有 Workflow 动作使用显式白名单；`answer_only`、`clarify` 和未来未知动作不能进入业务处理器。
- 每条内部命令携带目标 Workflow 的独立版本化 namespace。目标投影、决策和处理器返回值均为深拷贝，处理器不得污染 Supervisor 输入。
- 处理器返回值必须保持 conversation、workflow ID 与 kind 身份；任一变化均拒绝。处理器异常原样上抛，不跨业务类型 fallback。
- 本片 dispatcher 只返回经过校验的新投影，不更新 Supervisor 投影；interrupt/resume、LangGraph `Command` 转换和投影顺序留给 M02.3。
