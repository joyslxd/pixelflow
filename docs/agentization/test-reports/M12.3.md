## 实现合同

- `resolveSupervisorRuntimeNotice()` 相当于前端展示 Service：它把 reducer 的 run、compression 和 inputQueue 状态转换为稳定 ViewModel，页面和组件不直接解释 SSE 供应方字段。
- `WorkspacePage` 只装配当前 Supervisor 状态，`ChatPanel` 在 Composer 上方挂载独立 Notice；压缩状态不写成聊天消息，也不会污染历史消息。
- 压缩开始和真实 M04 的 `status/action/step` progressed 事件使用不确定进度；只有 payload 或 Snapshot 存在合法百分比时才展示精确进度条，显式非法百分比继续进入固定 fatal 状态。
- 完成态仅在 run 继续运行时展示，失败态使用可恢复语义；组件不展示摘要正文、token、prompt、异常字符串或其他内部信息。
- 排队数量和位置只以 reducer `inputQueue` 中 `status=queued` 的项目为权威；`sending`、`processing`、`accepted` 和 `failed` 不计入 badge，压缩兼容字段中的旧计数不参与展示。
- 服务端归属不是 `supervisor_v1` 时传入 `enabled=false`，因此 `frontend_v2` 继续保持既有 UI 和旧 runner 行为。
