## 实现合同结论

- `OperationStartCoordinator` 先创建或回读稳定 Operation，再领取非重入 start lease；并发请求只有胜者调用 Provider `start`，竞争者只回读同一内部 job。Authorization 和原请求只透传该次 Adapter 调用，Memory/SQLite 均不保存。
- start 阶段 402 没有 provider job 可继续，因此释放 start lease并返回固定 `OperationStartQuotaPausedError`；用户充值后显式重试同一 Operation。未知 start 结果保留租约，避免自动重复启动。
- `OperationRecoveryRuntime` 只扫描已持久化的 provider job ID。关闭取消并等待本进程后台任务，不清除正在执行的数据库租约；新进程在租约过期后继续查询原 job，不调用 Provider start。
- 每个恢复候选独立失败，坏 Provider/Repository/Graph 候选不能阻塞同批其他任务或永久终止后台循环。日志不包含异常字符串、用户内容、供应商响应或凭据。
- status 返回后重新读取时钟；若调用跨过租约期限，旧 worker 不能排期、暂停或提交终态，新 worker 在过期边界接管。
- status 阶段 402/`quota_paused` 保留原 Operation 和 provider job ID，清除自动轮询时间；用户动作只重新安排同一 job 查询。status 404 固定映射 `provider_job_expired`，原子落为 `expired` 和唯一完成事件；人工恢复只返回 `new_attempt_required`。
- SQL 完成候选通过 Event/Operation JOIN 在数据库内过滤 owner、conversation、job ID、终态和 payload status，按 outbox ID 排序后应用 `scan_limit`；无效前缀不会饿死真实候选，也不会全量物化或产生 N+1 查询。
- 未装配尚未交付的 M08–M11 真实 Workflow/Provider，没有新增配置、表、字段、索引、migration、HTTP API、Router 或 content-app 合同。
