## 故障复现与根因

历史测试对话 `4c054436fece44d39282391aece78eb7` 在约 4 秒内产生 81 次 Conversation `PUT`。服务端 Snapshot 显示 Turn 停在 `accepted`，没有 Workflow、结果或可见错误。

根因包含四层：

1. dev 配置声明 `primary / [video] / 100%`，创建 Service 仅依据配置和首轮 intent 就把视频冻结为 `supervisor_v1`。
2. Gateway 实际没有注册消费 live Turn 的视频 Graph Handler；M13.2 的 `SupervisorReplayRuntime` 和测试 fake 只证明回放合同，不等于线上 handler 已装配。
3. 前端主接力 effect 把未执行的 `accepted` Turn 移出 pending 后，inputQueue 恢复 effect 又立即重建同一 pending，两者互相触发 Conversation 自动保存；同时 R1 的空 Supervisor Workflow 投影会覆盖 v2 任务看板。
4. 历史会话没有“配置允许”和“live Handler 已安装”的可执行就绪证据，前端也没有可用于一次性收敛和解释失败的服务端保留字段。

修复前的第二轮真实复验在 6 秒内仍捕获 25 次 Conversation `PUT`，由此定位 inputQueue 重建竞态。最终修复后，历史 pending 清零，服务端只持久化 1 条中文解释消息；随后 6 秒稳态 Conversation `PUT` 为 0。新视频对话冻结为 `frontend_v2`，R1 Turn 正常登记并由 v2 单次接力，没有重复 start。

## 修复合同

### Runtime 就绪门禁

- `AgentRuntimeService` 新增 `primary_execution_intents`，并校验它必须是配置 `enabled_intents` 的子集。
- 新对话只有同时满足 `mode=primary`、100% 覆盖、intent 命中配置范围和 intent 命中 live handler 就绪集合，才能冻结为 `supervisor_v1`。
- Gateway 当前显式使用空就绪集合，启动日志打印实际集合，避免把“配置允许”误报成“执行链已安装”。
- Runtime 在服务端保留命名空间写入 `primary_execution_ready`；前端只信任该字段，不接受普通 context 伪造 live Handler 就绪状态。
- R2 定向测试显式注入 `("video",)` 验证未来真实 handler 装配后的 Supervisor 归属；默认装配测试验证安全接力 v2。

### 前端归属与恢复

- `supervisor_v1` 的 `accepted` Turn 只等待后端执行，不由 assist 提前确认或删除。
- `supervisor_v1` 进入 `failed/completed` 权威终态后收敛本地 pending；历史会话缺少 live Handler 就绪证据时不再从 inputQueue 重建 pending。该恢复先按会话稳定消息 ID 持久化一次中文说明，再写入 `agent_runtime_unavailable_notice_version=1` 并一次清空全部 pending；进程在两次写入之间退出时，刷新只补齐 marker 和清理，不重复消息。
- R1 统一消息投影继续服务 `assist/primary + frontend_v2`，但 Supervisor Workflow 只在真实 `supervisor_v1` owner 下投影，不能清空 v2 `workflowProgress`。
- 快照应用显式接收服务端响应的目标 Conversation ID，不依赖 React 渲染时序中的可变 ref。
- 分镜画布没有对应动作 Handler 时，保存和生成主按钮进入真实禁用态，不再显示可点击但无响应的假动作。

### 权威 Artifact

- 分镜“保存”按钮调用独立异步保存处理器，先更新权威消息再关闭画布。
- 删除全局素材先 `PATCH` 更新后的完整场景包 Artifact，再更新本地画布和成功提示。
- 已存在场景包消息时，刷新恢复只使用权威消息里的 `global_assets/scene_packages`；Conversation context 只在没有物化消息时负责补建，不得覆盖后续编辑。
- 视频“无意见，结束”先把 `videoAccepted=true` 写入权威视频 Artifact，再等待 `video_accepted` Conversation Snapshot 落库，最后显示成功提示。
- 刷新后最终视频保持“视频流程已结束”，任务看板保持“导出交付已完成”，当前版本不再出现可重复确认按钮。

### QC 严格作用域

- 优先使用后端 `target_scene_ids/affected_scene_ids`。
- 两者都为空时，只有用户明确写出“修改/修复/重生成第 N 个分镜（或第 N 段）”才提取对应 scene ID。
- “不要/不用/无需/不/别修改第 N 个分镜”等否定式表达不得命中兜底作用域。
- “调整一下”“更有冲击力”等模糊反馈继续返回空作用域，禁止默认整片重生成。
