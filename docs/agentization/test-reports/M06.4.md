## Operation 完成与恢复合同结论

- `ProviderJobSnapshot` 只有 `succeeded/failed/timeout` 能进入本片完成通道；`polling/paused_quota` 保持非终态，留给 M06.5 的重启与人工恢复语义。
- Memory Repository 在 Operation/Event 双写锁内，SQL Repository 在同一个写事务内，原子更新 Operation 终态、清除轮询计划/租约并追加 `external_job.state_changed`。事件身份碰撞、sequence 冲突或终态冲突全部回滚，不留下半状态。
- 完成事件 ID、cursor 和 run ID 只从内部 job ID 的带版本 SHA-256 派生；事件 payload 仅保留内部 job、provider job、workflow、stage/version/attempt、终态、安全 reason/message 和 M06.3 已校验业务结果，不写请求摘要、幂等键、Authorization 或供应商原始错误。
- 重复观察完全相同终态回读同一 Operation 和事件；不同终态、provider job ID 错配、owner/conversation 错配、无效/过期 lease 和事件身份碰撞均 fail-closed。
- `OperationCompletionDispatcher` 只按稳定事件 ID 领取指定完成事件。通用 Outbox claim 必须先检查最小未发布 sequence：队首为完成事件时返回空，不能越过它领取后续普通事件；Dispatcher 确认完成事件后才可继续。一个有效租约内只有一个 worker 调用 Graph，过期后才能接管。
- 完成记录中的 Operation、事件 envelope、payload 和嵌套业务结果全部深度只读，并能解冻为普通 JSON 稳定序列化。Graph Port 收到同样只读的原 workflow namespace 完成事件和 `idempotency_key=event_id`，不得重新调用 Provider start。Graph 调用失败不确认 Outbox，异常内容被替换为固定安全错误。
- Dispatcher 在 Graph 返回后重新读取完成时钟；不能用领取前的旧时间绕过租约过期检查。Graph 执行期间租约已经过期或被其他 worker 接管时，当前 worker 不能确认 Outbox，后续只重放同一事件 ID。
- Provider 成功而 Graph 尚未调用时，重启只读取已持久化完成事件；Graph checkpoint 已保存但 Outbox 尚未确认时，接管 worker 仍携带同一事件 ID，Workflow 端据此去重，业务恢复只生效一次。
