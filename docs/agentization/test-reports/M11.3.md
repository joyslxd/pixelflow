## 实现合同

- 新增 `VideoSceneGenerationWorkflowService`，首次生成必须为权威场景包中的每个分镜分别领取 `OperationPort` Operation；恢复只查询原 Operation 和原 Provider job，禁止按调用方给出的子集跳过分镜或创建第二个任务。
- pending 请求在启动、恢复、投影和终态回写边界都从权威场景与合同机械重建，并校验模型、比例、清晰度、声音、真实整数秒时长、Prompt、参考 URL、生成 mode 和业务幂等键。
- 新增视频专用 `VideoSceneAtomicOperationPort` 扩展合同。终态必须原子绑定 stage version、Operation 身份、Provider job ID、status 与 result hash；M06 尚未提供真实原子适配，因而真实终态接线必须失败关闭，不能退化为普通非原子写入。
- 成功终态冻结 `task_id/video_url/mode/endpoint/raw`，失败终态冻结 `error/attempts/retryable/quota/raw`；恢复时重新计算并核对 terminal claim，拒绝并发 success/failure、成功 URL 替换和把不可重试失败篡改成新计费重试。
- HTTP 402 与额度不足业务文案会立即阻止后续 Provider start。只有可证明为 `CREATED` 且没有 `provider_job_id` 的兄弟 Operation 才冻结为未启动；已进入 `POLLING` 的兄弟继续查询原任务。额度批量冻结允许在中途崩溃后按同一 result hash 幂等补完。
- 单镜修改只允许故事线、镜头描述、旁白和引用资产；身份、顺序、时长、转场及供应商合同字段不可修改。“已授权编辑谱系”与“待重生成 dirty 集合”分别持久化，重生成成功只清除 dirty 标记，不删除编辑谱系。
- 非空未知 `generation_types` 必须失败关闭；分镜时长必须属于实时 `durations_sec`。错误摘要和值内 URL 查询参数、Authorization、token、API key 等敏感信息均经过安全清洗。

1. 初始 RED：专项测试引用尚不存在的分镜生成 Service 与状态 DTO，先建立最小逐镜 Operation 骨架后转绿。
2. 恢复与部分失败 RED：刷新可重复领取、成功兄弟被重跑、失败重试范围过宽；改为权威 Operation 恢复和仅领取 retryable/quota-paused dirty 分镜后转绿。
3. 额度暂停 RED：402 后仍可启动后续任务、已启动兄弟被错误冻结、批量冻结崩溃后无法重放；区分未启动与 `POLLING` Operation 并校验 terminal hash 后转绿。
4. 原子终态 RED：普通 Operation Port 可写终态、并发 success/failure 可覆盖、成功结果可换 URL 或缺少 Provider job ID；引入 `VideoSceneAtomicOperationPort` 和持久化 terminal claim 后转绿。
5. 权威请求 RED：恢复时模型、比例、时长、Prompt、URL、mode 和幂等键可被伪造；每次从场景包与合同机械重建并逐项比较后转绿。
6. 单镜修改 RED：跨镜、身份字段和非授权供应商字段可修改，重生成后编辑谱系被清空；拆分授权谱系与 dirty 集合并收紧允许字段后转绿。
7. 能力与安全 RED：未知非空 `generation_types`、实时不支持的时长、不可重试失败伪造成可重试、值内凭据及 URL 查询参数泄漏；增加 fail-closed 能力校验、失败事实绑定和递归清洗后转绿。
