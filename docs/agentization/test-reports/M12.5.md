## 实现合同

- `workspaceProjection` 相当于前端 Application Service：Controller 层的 Hook 只取得 Snapshot/SSE DTO，Service 严格校验并转换，Reducer 作为单一 Store 投影消息、Workflow 和 interrupt，页面不直接猜测供应方字段。
- Snapshot 的持久化消息替换 Supervisor 历史页面状态；消息按 `payload.client_message_id` 优先、否则按 `message_id` 建立稳定 UI ID，材料与 Artifact 深复制，Artifact 和消息不拆成两套事件。
- `message.upserted` 和 `workflow.progressed` 同时接受冻结合同的直载 DTO 与当前后端已落地的 `message/workflow` 包装；两种形状最终进入相同严格投影，不能绕过角色、Artifact 类型、Workflow 枚举、版本、时间和对话归属校验。
- Workflow 按 ID 原位更新，旧 `stage_version` 或旧 `updated_at` 只推进事件 cursor、不回退业务状态；相同版本与时间却内容冲突时失败关闭。
- 最新 Workflow 映射为现有 `WorkflowProgressSnapshot`，继续由 `deriveWorkflowTaskBoard()` 负责图片、视频、PPT 步骤和 Artifact 下载状态；`video_analysis` 不生成看板。
- Snapshot/SSE 的跨对话消息、Workflow 或 interrupt 均失败关闭；sequence gap 不应用越级 UI 数据，切换对话后旧 controller 已有生命周期取消合同继续生效。
- 当前 interrupt 仅在它所属的 Supervisor 状态与目标对话一致时用于 M12.4 `respondToInterrupt()`；普通 Turn、旧 `frontend_v2` runner 与供应商 `/start` 动作合同保持不变。
