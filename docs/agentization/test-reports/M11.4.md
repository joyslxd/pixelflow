## 实现合同

- `VideoPostProductionWorkflowService` 只消费 M11.3 全部分镜成功、无 pending/失败/dirty 的人工审核状态。merge 请求按 `scene_index` 机械排序；单分镜仍领取 Operation，但直接复用当前 HTTPS 视频且不调用供应商 merge。
- `VideoPostProductionAtomicOperationPort` 使用两阶段启动协议：先在 `CREATED` 上原子绑定 30 秒外调前租约，过期后才允许安全接管；随后原子标记 `POLLING` 才进入 Skill。mark 后即使进程崩溃也失败关闭，不自动接管或二次调用供应商。
- 成功/失败终态在可信 Repository 原子保存 `ExternalJobRef`、stage version、result type、result hash 与完整安全载荷，并支持按 `job_id` 读取。重复 merge/QC 不再调用 Skill，而是恢复首次终态业务载荷；checkpoint 自洽哈希不能替代 Repository 事实。
- Operation 幂等键绑定机械重建请求的 SHA-256。QC 请求冻结清洗后的首次 `user_feedback`，retry 不得改写；pending、终态、修改和结束边界都会重算原请求并核对可信 Operation identity/terminal claim。
- merge 成功后进入 `video_review`，用户可以直接明确结束；只有用户提出修改时才启动唯一 QAAgent QC。merge 后不得直接修改绕过 QC；QC 结论或 QC 调用失败后，修改循环复用 M11.3 单镜白名单和 dirty 重生，回交后的 stage/context version 严格递增。
- merge/QC HTTP 402 与额度文案暂停当前阶段，只有用户明确重试才领取下一 attempt。错误、用户意见和供应商 raw 会清除 Authorization、Bearer、token、API key、secret 及 URL 查询参数。

## TDD 与缺陷关闭

1. 初版专项先冻结 merge 顺序、单镜直通、QC DTO、402、修改循环、人工结束、稳定 Artifact 和非原子 Port fail-closed；首轮实现转绿后进入独立审核。
2. 首轮审核发现重复调用可能二次计费、普通 Port 外调后才失败、402 泄漏、伪造 review 可结束、版本倒退、绕过 QC 和 feedback 未冻结。重构期间专项曾得到 `6 failed, 5 passed`，随后引入原子启动权、终态 claim、脱敏、版本提升和 QC 前置，专项转为 `13 passed`。
3. reviewer 进一步用完整自洽 checkpoint 重算复现伪造结束 RED。新增可信 Repository 终态读取、完整业务载荷恢复和两阶段启动租约后，伪造状态在 `finish()` 被拒绝；重复 merge/QC 恢复首次业务结果。
4. reviewer 最后复现 QC pending 与 terminal 后可改写 feedback。幂等键加入权威请求摘要，terminal claim 改为校验原始阶段请求，并增加两组篡改对抗；最终专项为 `16 passed`。
5. 定向对抗覆盖 URL、分镜顺序、attempt、幂等键、完整 checkpoint、feedback+key 双重伪造、供应商身份漂移、mark 前 lease 接管和 mark 后禁止接管；所有缺陷均经 RED/GREEN 关闭。
