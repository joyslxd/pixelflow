## 实现边界

- 新增 `projectLegacyConversationSnapshot`，作用类似 Java 的 Adapter/Assembler：把旧 Conversation DTO 和 Message DTO 统一投影成稳定只读 ViewModel，不在 adapter 内恢复任务或触发任何外部调用。
- 以 fixture 固定 14 组 pending camel/snake 双字段；等价值只归一一次，冲突值、非法对象或不属于当前对话的值全部 fail-closed。
- 以 fixture 固定当前 18 类 artifact；兼容持久化 `payload.artifact` 和旧 ViewModel 直接 `artifact`，双字段冲突时拒绝快照。
- 历史快照没有编排归属时默认 `frontend_v2`；只要 legacy pending 尚未排空，即使数据被误标为 `supervisor_v1` 也保持旧 Runtime 恢复权，避免双 owner 和重复计费。
- 消息投影过滤 system 消息，优先使用 `payload.client_message_id`，稳定消解重复 ID 并同步 artifact 引用；`conversationId` 与 `conversation_id` 任一归属异常都拒绝。
- context、pending、materials 和 artifact 均执行 JSON 深拷贝与有限值校验；非法输入只返回固定中文错误，不包含原始内容。
