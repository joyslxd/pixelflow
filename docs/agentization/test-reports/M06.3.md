## Provider Adapter 合同结论

- `ExistingJobService` 只暴露异步 start/status；start 显式接收本次 Authorization 与 operation 幂等键，Adapter 不缓存调用参数，status 只查询调用方给出的原 provider job ID。
- 现有 Mapping 或 Pydantic DTO 的 `running/queued/pending/polling/processing/in_progress` 统一映射为 `polling`；`succeeded/success/completed/done` 统一映射为 `succeeded`。
- `failed/error/cancelled` 和已知状态下的显式 `ok=false` 映射为业务失败；未知状态始终 fail-closed，不能靠 `ok=false` 猜测。
- 直接 `status_code` 或 `httpx.HTTPStatusError.response.status_code` 的 HTTP 402、真实 `quota_paused` 状态、结构化额度标记和受控额度文案优先映射为 `paused_quota`；内置 `TimeoutError` 与 `httpx.TimeoutException` 映射为 `timeout`。
- provider job ID 必须满足受限字符和 255 字符上限，URL、空白或疑似凭据形态一律拒绝；缺失、冲突或与 status 查询目标不一致时也拒绝映射，不会查询替代 ID 或重新 start。
- 业务请求和稳定结果中的 Authorization、token、API key、secret、password、credential 键或凭据字符串在边界处拒绝；完整 HTTP(S) URL 的 userinfo、query 和 fragment 也不能进入稳定 Snapshot。业务失败、402、超时和未分类异常均不回显供应商错误原文、URL、token 或 traceback。
- Adapter 对现有 v2 DTO 的明确 `raw/raw_response/provider_response/response_body` 字段做递归剔除，剩余成功或轮询结果必须满足有限 JSON 合同。公开 Snapshot 固定 outcome、reason、message 和失败态空结果的一一对应，顶层及嵌套业务结果均不可变，序列化前还会重新执行安全校验并投影为普通 JSON。
