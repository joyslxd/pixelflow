## Operation 合同结论

- operation 幂等身份固定为 `workflow_id + stage + stage_version + attempt`，键使用 `operation:v1:sha256:<hex>`，结构化 JSON 消除分隔符歧义。
- 供应商请求按稳定键排序、紧凑分隔符和 UTF-8 计算 SHA-256；非 JSON 值及 NaN/Infinity fail-closed。Coordinator 只接收摘要，不持久化原始请求、Authorization、token 或密钥。
- 相同 owner、conversation、身份和请求摘要的顺序/并发 start 只保留一条 `created` operation，并回读同一内部 `job_id`。
- 相同幂等键被不同 workflow、conversation、stage、stage version、attempt 或请求摘要复用时统一抛 `OperationConflictError`；其他 owner 既不能读取也不能复用记录。
- 状态表覆盖 `created/polling/succeeded/failed/timeout/expired`：同状态重放幂等，活动状态只向前进入允许状态，终态不得重开或互相切换。
