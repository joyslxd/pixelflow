## Turn Inbox 合同结论

- `enqueue_turn()` 相当于带业务幂等键的 Repository 保存：同一 `conversation_id + client_input_id` 的同 owner 重试返回首次持久化快照，不新增 Turn；`create_turn()` 继续保留“重复即冲突”的严格底层语义。
- `turn_id` 和幂等键继续保持全局唯一；其他 owner 占用相同标识时 fail-closed，读取仍按 `user_id` 过滤，不泄露既有 Turn。
- `claim_next_turn()` 只考虑 `accepted/queued/processing`，按 `inbox_sequence` 选择最早 Turn；已有 `processing` 时不领取后续 Turn，终态记录被跳过，不同 conversation 可独立领取。
- Memory 实现在单事件循环内没有中途挂起点，保存与状态转换保持原子并返回深拷贝；SQL 实现在同一事务中锁定活跃行并提交 `processing` 状态。
- 非 SQLite 数据库使用 `SELECT ... FOR UPDATE`；SQLite 同 Engine 使用共享异步写锁，跨 Engine/进程使用 `BEGIN IMMEDIATE` 数据库写锁。并发入队只保留一个 Turn，并发领取只产生一个 `processing` Turn。
