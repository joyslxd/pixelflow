## 实现边界

- 新增 `VideoPlanningWorkflowService`，按 `intake → direction_generation → direction_review → plan_generation → plan_review` 执行显式状态转换；表单关闭进入 `form_cancelled` 终态，方向审核支持显式重新生成。
- 创意方向必须恰好三个且由用户显式选择，不提供倒计时默认方向；每次合法转换同时递增阶段版本和上下文版本。
- `VideoPlanAuthoritySnapshot` 使用规范 JSON 和 SHA-256 冻结 Plan Markdown、创作合同、分镜蓝图、资产清单、时长及完整版本历史，并向调用方返回独立副本。
- 初始 Plan 必须逐字段继承采集阶段确认合同；场景图规格只允许三项完整补充，比例和尺寸必须属于图片模型能力范围。
- 当前载荷和每个历史版本都强制保留用户确认状态、精确总时长、单镜 4–15 秒、连续时间线、蓝图时长数组和资产清单并集。
- 修订只能追加一个连续版本且不得改写历史前缀；在本片没有模型重新确认入口的边界内，合同版本、意图、模型选择模式、视频/图片模型及两份能力快照不可漂移。合法风格、画幅、声音和受支持场景图规格修订仍可发布。
- 历史恢复只能激活既有版本，不追加重复历史；旧 Service 仅裁剪正文首尾空白时重新绑定历史原文，其他差异继续失败关闭。
- 通用 `WorkflowRecord` 只投影创作合同和稳定 Artifact 引用，完整 Plan 权威数据不进入可压缩消息通道。
