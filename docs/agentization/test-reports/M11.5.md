## 实现合同

- 新增 `VideoDeliveryWorkflowService`，只消费 M11.4 已合并、无 pending 后处理 Operation，且正在等待人工审核或已经人工结束的视频状态。剪映请求严格使用当前版本全部成功分镜，按 `scene_index` 排序并复用既有 FNV-1a `storyboard_version_id`；合并视频绝不进入剪映分镜 DTO。
- capability 不可用或查询失败时不创建空 Operation。可用时沿用两阶段原子启动合同；默认总等待上限为 1800 秒，超时原子落为可显式重试的 `timeout`。
- 刷新只查询原 `job_id`。M11.3 分镜终态、M11.4 后处理终态和剪映终态都回查可信 Repository，并交叉验证 Operation identity、stage version、请求摘要、结果摘要和来源 Artifact；本地自洽 checkpoint 不能替代权威事实。
- 同一版本的运行中任务和未过期成功结果幂等复用；`failed/timeout` 只有用户显式重试才创建下一 attempt。失败结果移除 Provider ID、下载 URL、文件名和过期时间，只保留经过敏感信息过滤的公开消息。
- 新分镜版本保留旧 `jianyingDraftRecords` 历史入口，但清除旧合并视频的最终下载证据。剪映 ZIP 下载只写草稿历史，不完成“导出交付”；只有当前合并成品视频的明确下载才投影 `deliveryDownloadedAt/deliveryDownloadedUrl`。
- 当前候选没有注册 Supervisor handler，没有改写现有剪映 Router、进程内 job registry、PowerMem 或第三方/content-app 调用合同；生产 v2、R1 `assist` 和 Feature Flag 行为保持不变。

## TDD 证据

1. 初始 RED：专项测试引用尚不存在的交付 Service 与状态 DTO；建立最小交付状态和剪映请求后转绿。
2. 幂等与 capability RED：不可用 capability 会创建空 Operation，pending 状态可绕过可信恢复；改为 capability 前置检查、Operation identity 校验和可信终态恢复后转绿。
3. 安全终态 RED：失败结果可能保留 Provider ID、URL、文件名或非公开错误；改为按状态归一化公开 DTO，并清除失败结果的非公开字段后转绿。
4. 恢复边界 RED：`not_configured`、显式 retry envelope 和完整 checkpoint 篡改存在旁路；冻结请求摘要、retry 标志、attempt 与幂等键，并在终态应用时再次交叉验证后转绿。
5. 权威分镜 RED：本地伪造成功分镜或 capability 状态可派生新版本；为 `VideoSceneAtomicOperationPort` 增加只读终态 claim，并逐镜回查可信 Repository 后转绿。
6. 超时 RED：Skill 没有受 M11.5 总等待上限约束；增加默认 1800 秒 `asyncio.timeout`，并把超时映射为安全、可重试终态后转绿。
