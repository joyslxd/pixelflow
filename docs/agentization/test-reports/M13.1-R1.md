## 实现与合同

### Turn、队列与恢复

- 新增统一 Runtime Service 和 `/agent/conversations/{conversation_id}/turns/start`、Snapshot、SSE、job 查询入口。
- Turn 登记在同一 SQL 事务中完成 conversation context CAS、可见用户消息、Turn、context version 和前两条事件；同一会话仅一个 `accepted/processing` 执行 owner，后续输入按 Inbox 顺序进入 `queued`。
- Memory/SQL 两套 Store 均覆盖原子登记、并发幂等、排队、完成当前 Turn 后领取下一 Turn和事件恢复。
- 前端 pending Turn 使用稳定 UUID；恢复上下文 PUT 成功后才向注册 effect 暴露，并立即按同一 UUID 乐观显示用户消息。
- 同一 conversation 的 pending Turn 和旧消息 job 上下文写入共用串行写通道，调用方在临界区内以 `(latest) => next` 更新，避免快速双发发生全量 PUT 覆盖。

### 压缩与上下文安全

- 60% 阶段实际复用 M03 `ContextPayloadExternalizer`，大型 recent message payload 按用户/会话归属外置；完整当前输入及其 materials、reply、artifact refs 不外置。
- 75%/硬门槛阶段复用 M04 SummaryBuilder 与事实验证，首版摘要确定性保护用户目标、业务事实、负向约束、未决问题、稳定 ID 和 Artifact 引用；遗漏时 fail-closed。
- 85% 分层摘要按 Workflow stage/context version 建立覆盖证据，只有重新组装后的实际上下文严格缩小时才保存；扩张时不保存、不伪造覆盖。
- 创作合同继续留在权威 Workflow/业务通道，不进入 M04 摘要器；回归测试以规范 JSON SHA-256 证明 hierarchy 前后权威 `creation_contract_snapshot` 未变。
- 压缩租约、fencing token、事件、输入队列和恢复 Snapshot 共用持久化仓库。

### 旧流程等价与接力安全

- R1 `assist` 只挂载统一会话基础设施，图片、视频、PPT、视频分析仍由旧 v2 runner 推进。
- 旧消息 job 只有在 job 用户、会话、稳定消息 ID、状态和对应 Turn 状态均匹配时才建立 `legacy_handoff` marker。
- 新 marker 只允许 `accepted/processing` Turn；真实 job 也不能让 queued Turn 越序接力。
- Snapshot 会安全清理历史非法 marker；`completed` 只用于恢复“合法 marker 已写、Turn 已完成、待补事件或清理 marker”的中断窗口。
- marker 与客户端 pending context 在同一 Conversation Store 临界区提交；接力中断后 Snapshot 幂等补偿，刷新不重复启动旧消息 job。
