## Repository 合同结论

- `AgentRuntimeRepository` 相当于 Java 的 DAO 接口；Memory 与 SQL 两个实现提供相同的创建、按 ID 读取和 conversation 列表读取能力。
- 全部 SQL 读取直接在数据库 `WHERE` 中组合 `user_id` 与业务 ID/conversation 条件，不先取出其他用户记录再做应用层判断。
- Memory 模拟数据库全局主键和唯一业务键；SQL 将 `IntegrityError` 归一为不包含记录内容的 `AgentRuntimeRecordConflictError`。
- 所有持久化列长度在两个实现进入存储前统一校验；空字符串、纯空白 owner 和超出数据库列上限的输入统一拒绝。
- 所有带时区时间在写入前统一转换为 UTC-aware；naive datetime 统一拒绝。数据库读取到无时区 UTC 墙上时间时只恢复 UTC 标记，避免 SQLite/MySQL 偏移。
- Memory 保存与返回深拷贝；双实现合同覆盖 Workflow pending job、Turn decision patch、Summary JSON 和 Event payload 的嵌套隔离。
- 稳定排序覆盖 Workflow/Operation 同时间 ID tie-break；Turn 使用数据库接收顺序，Summary/Event 使用版本或 sequence。
